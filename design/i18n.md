# Internationalisation

Turkish and English, **both first-class**. Neither is a partial translation of the other,
and neither is the "real" version.

- **Last updated:** 2026-08-15
- **Related:** [../docs/adr/0001-stack.md](../docs/adr/0001-stack.md),
  [../docs/adr/0002-cms.md](../docs/adr/0002-cms.md), [content-model.md](content-model.md),
  [brand.md](brand.md)

`ASSUMPTION:` locale codes are the short forms `tr` and `en`, in both Strapi and the App
Router, with **`en` as the default**. The default matters: it is the locale a missing CMS
translation silently falls back to.

## Routing

**Both locales are path-prefixed. Neither is served from the bare root.**

```
/en/missions
/tr/gorevler
```

`/` redirects. `ASSUMPTION:` middleware reads `Accept-Language` and falls back to `/en/`,
issued as a **307** so it is never cached as permanent. A 301 here is close to
unrecoverable — browsers and intermediaries cache it, and a visitor who once landed on the
wrong locale keeps landing there.

Note the cost of the sniff: `/` cannot be statically served, and this middleware runs on
every request that reaches it. If that proves undesirable, replace it with a fixed
redirect to `/en/` — the language switcher and `hreflang` do the rest of the work, and a
static redirect is one fewer moving part.

## Localized URL segments

Segments are **fully localized**, not merely prefixed. `/tr/missions` would be a Turkish
page at an English address, which undercuts "both first-class."

This is the mapping table. It is the source of truth; the language switcher and the
sitemap both read from it.

| English | Turkish | Notes |
| --- | --- | --- |
| `about` | `hakkimizda` | |
| `schedule` | `takvim` | |
| `galactic-summit` | `galactic-summit` | **Brand name — unchanged** |
| `missions` | `gorevler` | |
| `events` | `etkinlikler` | |
| `projects` | `projeler` | |
| `alumni` | `mezunlar` | |
| `join` | `bize-katil` | |
| `timeline` | `zaman-cizelgesi` | Has a route, stays out of the navbar |
| `news` | `duyurular` | |

**Turkish slugs are transliterated to ASCII.** `gorevler`, not `görevler`;
`zaman-cizelgesi`, not `zaman-çizelgesi`. Percent-encoded URLs are legal but they are
unreadable when pasted into a message, break in some link previews, and look broken to
the exact sponsor audience the site is trying to impress. This applies to entity slugs
too, not just section segments.

**Event brand names stay English in both locales** — Galactic Summit, Stellar Talk, Nebula
Night. They have their own logotypes and a sponsor-facing identity; giving them a second
name splits their recognition. Generic section names translate. See
[brand.md](brand.md) for the full rule.

## The language switcher

**Visible on every page.** It must **preserve the current route**, not dump the user on
the home page.

With localized segments this is real work rather than a prefix swap: the switcher resolves
the equivalent route through the mapping table above, and through the entity's per-locale
slug for detail pages.

Failure modes to handle explicitly:

- **The equivalent page does not exist** (CMS content in one locale only) → switch to the
  other locale's home page and say so, rather than 404ing.
- **The entity has no slug in the target locale** → cannot happen for git content, which
  CI blocks; for CMS content, fall back to the default locale's slug.

`ASSUMPTION:` the switcher shows "TR / EN" rather than flags. Flags represent countries,
not languages, and Turkish is not confined to one flag.

## hreflang, canonical, and the sitemap

With both locales prefixed, omitting these means the two versions **compete with each
other** in search results.

Every page carries:

- `hreflang` alternates for both locales, plus `x-default` pointing at the `/en/` version.
- A `canonical` pointing at itself — its own locale's URL, never the other locale's.

`sitemap.ts` emits `alternates.languages` for every route in both locales, which is the
Next.js App Router's supported mechanism for this and keeps one source of truth with the
mapping table.

`ASSUMPTION:` `robots.txt` and a 404/500 page are in scope. The preview route is
`noindex` ([ADR 0002](../docs/adr/0002-cms.md)).

## Missing translations behave differently by source

This is deliberate, and the difference is the point.

### CMS content — fall back silently. Never 404.

An editor who has written the English version of an announcement but not the Turkish one
should not be creating broken pages by working in a normal order. Strapi's own i18n
handles this; the Turkish visitor sees the English text.

### Git content — fall back with a **visible** notice

> Bu sayfa henüz Türkçe olarak mevcut değil.
> This page is not yet available in English.

Linked to the available version.

Silent fallback on a bilingual site reads as a bug rather than as incompleteness. For
missions and the timeline — the credibility content — an untranslated page should look
*deliberately* incomplete rather than accidentally English.

### How this coexists with the CI parity gate

These two rules appear to contradict each other. [ADR 0004](../docs/adr/0004-verification.md)
requires CI to assert that every git content directory contains **both** locale files — so
a missing translation could never merge, and the visible notice above could never render.

The resolution:

- **CI asserts both files exist and both declare a slug.** A missing file is a broken
  route under localized segments, so it must never merge.
- **A locale file may declare `status: incomplete`** in its frontmatter, with a minimal or
  placeholder body. That is what triggers the visible notice.

So the gate blocks the *broken* case (no file, no route) while the *incomplete* case stays
representable and visible. A translator's backlog is a normal state for a bilingual
volunteer-run site; a 404 is not.

## Content rules

- **Do not machine-translate and publish.** Both locales are first-class; a visibly
  machine-translated Turkish page is worse than an honest "not yet available" notice.
- **Dates and numbers** format per locale, but the underlying value is one
  locale-independent fact ([content-model.md](content-model.md)). Formatting happens at
  render, client-side for anything time-relative
  ([ADR 0001](../docs/adr/0001-stack.md), rule 3).
- **Turkish text will contain `ğ ş ı İ ç ö ü`.** The display face does not cover all of
  them, and this is a correctness rule rather than a stylistic one — see
  [brand.md](brand.md).
- **Turkish is usually longer than English.** Layouts must not assume English string
  lengths; navigation and buttons are where this breaks first. `Bize Katıl` versus `Join
  Us` is fine, but `Zaman Çizelgesi` versus `Timeline` is nearly double.
